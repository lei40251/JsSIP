# 共享白板发起端比例同步设计

## 背景

`demo/base-js/` 当前将白板 Konva Stage 直接铺满各端的共享浮层。标注坐标虽然以
0～1 归一化数据同步，但渲染时分别乘以本端 Stage 的宽和高，因此 PC 横向容器与手机
竖向容器会把同一图形拉伸成不同宽高比。

## 目标

- 白板发起端在打开白板时确定本次白板的逻辑宽高比。
- 被共享端按发起端比例等比显示，图形比例和相对位置保持一致。
- 本次白板打开后锁定比例；窗口缩放或手机旋转只改变显示尺寸。
- 保留现有公开 SDK API、SIP INFO 事件时序和归一化标注坐标格式。
- 兼容未携带宽高比字段的旧版 Demo。

## 方案

新增白板会话状态 `boardAspectRatio`，保存发起端打开白板时绘制区域的
`clientWidth / clientHeight`。比例只作为 Demo 标注协议 payload 的附加字段发送：

- `board:open`：在 payload 中携带 `aspectRatio`。
- `snapshot`：在 `payload.whiteboard` 中携带 `aspectRatio`，保证后加入或通过快照恢复的
  参与端获得相同比例。

接收端只接受有限正数范围内的比例。缺少或无效字段时不报错，继续使用当前容器比例，
保持与旧端兼容。比例范围采用 `0.25～4`，覆盖常见手机竖屏、桌面宽屏和超宽屏场景，
同时避免异常数据产生不可用画布。

## 布局与数据流

1. 发起端打开白板，浮层和工具栏完成显示后读取可绘制容器尺寸，并锁定比例。
2. 发起端将比例随 `board:open` 及后续白板快照发送给目标会话。
3. 接收端在打开或恢复白板前保存通过校验的比例。
4. `resizeInk()` 在白板模式下根据容器尺寸和锁定比例执行 `contain` 计算：
   - 画布宽高不超过容器；
   - 水平、垂直居中；
   - 白板背景和 Konva Stage 使用完全相同的位置、宽度和高度。
5. 浏览器窗口变化或设备旋转时重新计算显示尺寸，但不修改 `boardAspectRatio`。
6. 关闭或重置白板时清除本次比例，下一次打开重新取发起端当前比例。

现有 shape 坐标、线宽归一化、撤销/重做和橡皮逻辑不变。

## 兼容与异常处理

- 新端接收旧端：没有 `aspectRatio` 时沿用本端容器尺寸，不阻断白板。
- 旧端接收新端：忽略 payload 的附加字段，原有操作仍可执行。
- 非数字、非有限数或超出范围的比例：忽略字段，不关闭会话、不发送错误 INFO。
- 不修改 SDK 导出、`.d.ts`、默认 SIP 时序、Promise 行为或错误类型。

## 验证

在现有 `test/test-conference.js` Demo 标注测试中补充：

- 横向发起比例在竖向容器中等比缩放并垂直居中。
- 竖向发起比例在横向容器中等比缩放并水平居中。
- `board:open` 和 `snapshot` 能保存及恢复有效比例。
- 缺少或无效比例时使用兼容回退行为。
- 关闭白板后比例状态被清理。
